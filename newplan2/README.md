# drone2 写真誘導パラメトリック3Dモデル計画

- 作成日：2026-07-31
- 対象：`input/raw_photos/drone2` の上・下・前・後・左・右の6方向写真
- 対象機体：`drone2_petron_s`
- 実行環境：Windows、Blender 5.2、Python、Blender MCP

## 1. 結論

TripoSR、Hunyuan3D、Pixal3Dなどのローカル3D生成AIを主経路から外し、
**実寸値と6方向写真を根拠に、Blender Pythonで部品を決定的に生成して組み立てる方式**へ移行する。

この方式では、写真から完成メッシュを直接推定しない。次の順序でモデルを作る。

1. 実物から少なくとも1個の基準寸法を測る。
2. 写真上の特徴点と輪郭を、基準寸法に合わせてmm単位へ換算する。
3. 中央ボディ、アーム、モーター、プロペラ、プロペラガードなどを独立部品として生成する。
4. モーター中心を基準に4組を配置し、必要な箇所だけ前後左右差分を加える。
5. 6方向の参照カメラでシルエットを比較し、設定値を修正する。
6. 表示用メッシュ、回転軸、アンカー、衝突形状、質量特性を分けて出力する。
7. 同じ設定ファイルから `.blend`、GLB、評価画像、検査結果を再生成できるようにする。

## 2. この方式を採用する理由

画像生成AIの出力は、一方向から見た外観は近くても、側面の厚さ、独立部品、
回転軸、衝突形状を正しく復元できなかった。ドローンのシミュレーションでは、
写真らしい表面より次の情報が重要である。

- 4個のモーター中心位置
- 各ローターの回転軸と回転方向
- プロペラ直径とガード内径
- 中央ボディ、アーム、モーターの独立性
- 重心、質量、慣性モーメント
- 単純で安定した衝突形状
- 同じ入力から同じモデルを作れる再現性

これらは、生成AIよりも寸法パラメータと部品組立で管理する方が確実である。

## 3. 重要な前提

### 3.1 写真だけでは絶対寸法を確定できない

画像の画素数から比率は計算できるが、実物のmm寸法は少なくとも1個の基準寸法が
なければ決まらない。最初に次のいずれかを実測する必要がある。

- 左右モーター中心間距離
- 対角モーター中心間距離
- プロペラ直径
- ガード外径
- 機体の全幅

最も推奨する基準値は、写真でも中心点を取りやすい
**左右または対角のモーター中心間距離**である。製品仕様の公称値は補助値とし、
手元の実物をノギスまたは定規で測った値を優先する。

### 3.2 写真は完全な正投影図ではない

6枚は撮影距離、画角、被写体位置、傾きが統一されていない。このため、写真を
そのまま同じ縮尺の平面に貼っても一致しない。各写真へ個別のカメラ倍率、位置、
回転補正を持たせ、既知寸法またはモーター中心を基準に整列する。

### 3.3 推定値には確度を持たせる

すべての寸法に、`実測`、`写真推定`、`派生計算`、`仮置き`の区分を持たせる。
仮置き値を実測値と同じ扱いにしない。

## 4. MCPとスクリプトの役割

Blender MCPとバックグラウンドスクリプトは競合するものではなく、役割が異なる。

| 手段 | 主な役割 | 正規成果物への扱い |
|---|---|---|
| Blender MCP | シーン確認、参照ビュー表示、局所形状の試作、数値調整、スクリーンショット確認 | 調整結果を設定またはスクリプトへ戻す |
| Blender Python | 部品生成、組立、命名、アンカー設定、衝突形状作成、保存、GLB出力 | 正規の再生成経路 |
| 通常のPython | 設定検証、画像座標の換算、レポート、比較シート、回帰テスト | 正規の制御・検査経路 |

現在、Blender MCPはBlender側サーバーが起動していないため未接続である。
実装時はBlenderを起動して接続すれば対話操作できるが、ビルド自体はMCP接続が
なくても完走できる構成にする。

MCPで直接頂点を動かして終わりにはしない。採用した変更は必ず
`config/drone2_model.yaml`またはBlender Pythonへ反映し、再生成で再現できることを
確認する。

## 6. 採用する設計原則

1. Blender単位はメートル、設定値は人が扱いやすいmmで記述する。
2. 座標系は`+X=右`、`-Y=前`、`+Z=上`とする。
3. `drone_root`の原点は推定重心に置く。接地面を原点にはしない。
4. 同型部品は共有メッシュを使えるが、各ローターは独立Objectと独立原点を持つ。
5. 左右対称を初期値とし、写真で確認できた差分だけ上書きする。
6. 表示用形状と衝突用形状を別Collectionに置く。
7. Booleanを多用せず、プリミティブ、断面押出し、Curve、Bevel、Mirror、Arrayを優先する。
8. エクスポート時に負のscaleを残さない。
9. 回転軸、センサー位置、重心などはEmptyで明示し、GLB extrasへ出力する。
10. 写真との完全一致より、部品構造、軸、寸法、シミュレーション安定性を優先する。

## 7. 成功条件

最初の完成条件は、精密な工業CADではなく、シミュレーションに使える構造モデルである。

- 設定した全幅、全長、全高、モーター中心位置が許容差内にある。
- 4個のモーター、プロペラ、ガードが独立部品として存在する。
- 各プロペラの原点とローカルZ軸が回転軸に一致する。
- 部品名とアンカー名が規約どおりである。
- 表示用メッシュと衝突形状を個別にON/OFFできる。
- `.blend`とGLBを1コマンドで再生成できる。
- 6方向レンダーと元写真を並べた比較シートを生成できる。
- Godotで単位、向き、階層、各ローター軸を確認できる。

## 9. 最初に必要なユーザー入力

実装開始前に、実物から次の値を1個以上測る。第一候補は
`motor_center_diagonal_mm`である。

可能であれば、次も測ると初期精度が大きく上がる。

- 機体全幅
- 機体全長
- 機体全高
- プロペラ直径
- ガード外径
- 機体総質量

値がまだ得られない場合でも、比率モデルのBlockoutまでは進められる。ただし、
その段階のGLBは寸法未確定のため、物理シミュレーション用の正規モデルにはしない。
