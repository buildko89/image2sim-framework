# Task 3F: 外観・形状転写計画

## 目的

Task 3E で準備したリグ付き四足動物ベースモデルを、実画像、マスク、Hunyuan3D生成メッシュを参照しながら、猫らしい見た目と体型へ近づける方針を決める。

このTaskでは本格的なBlender編集や新規3D生成は行わない。次の実装Taskで迷わないよう、参照データの使い方、編集範囲、MVPでやること、後回しにすることを整理する。

## MVP方針

Task 3F以降のMVPでは、次の順で猫らしさを上げる。

1. 参照画像と静的メッシュをBlenderシーンに置く。
2. リグ付きベースモデルを破壊しない範囲でプロポーションを調整する。
3. マテリアル色を実画像に寄せる。
4. 必要なら耳、顔、尻尾の印象を軽く調整する。
5. アニメーションが破綻していないか確認する。
6. GLB/FBXで出力し、Godotで表示・再生確認する。

優先するのは、写真そっくりの高精度モデルではなく、ゲームエンジンで動く「猫として認識できるリグ付きモデル」を作ること。

## 転写対象

### 1. 毛色・模様

優先度: 高

方法:

- 実画像から主要な毛色を目視で決める。
- 最初はBlenderマテリアルのベースカラー調整で対応する。
- 複雑な模様はMVPでは手動ペイントまたは簡易マテリアル分けに留める。

MVPでやること:

- 胴体、顔、耳、脚、尻尾の基本色を決める。
- 必要なら濃淡2から3色程度の簡易パターンにする。

MVPでやらないこと:

- 写真からの完全自動テクスチャ投影。
- 毛並みの高精度再現。
- PBR毛皮シェーダー。

### 2. 体型・プロポーション

優先度: 高

方法:

- Hunyuan3D生成メッシュとマスク画像を参照し、Foxベースとの違いを見る。
- リグを壊さない範囲で、胴体、脚、頭、尻尾のスケールを軽く調整する。

調整候補:

- 胴体を猫らしく少しコンパクトにする。
- 頭部の印象を猫寄りにする。
- 尻尾の長さ・太さを実画像に寄せる。
- 耳の形状を尖りすぎない範囲で調整する。

注意:

- 骨構造を大きく変えない。
- メッシュだけを大きく変形しすぎない。
- アニメーション再生時の脚、首、尻尾の破綻を優先して確認する。

### 3. 顔・耳・尻尾

優先度: 中

方法:

- 顔の細部を完全再現するより、シルエットとして猫に見えることを優先する。
- 耳と尻尾は猫らしさに強く影響するため、必要に応じて軽く編集する。

MVPでの判断:

- Fox由来の長い鼻先が強すぎる場合は、顔まわりの見た目調整を優先する。
- 尻尾は動きに影響するため、ボーンとウェイトの破綻を避ける。

### 4. アニメーション保持

優先度: 高

方針:

- 見た目調整より、Armature、weight、animation clipの保持を優先する。
- 編集後に少なくとも `Idle`、`Walk`、`Jump_ToIdle`、`Gallop_Jump` を確認する。

Task 3Gへ渡す課題:

- sleep / lie-down 相当の動作をどう作るか。
- 既存の `Eating` または `Idle_2_HeadLow` を休憩・伏せ姿勢の代替に使えるか。
- 足の接地や体の浮き上がりがゲームエンジンで問題ないか。

## 推奨ワークフロー

### Step 1: Blender参照シーン作成

入力:

- `output/rigged/cat_base_rigged.blend`
- `input/masks/*_cutout.png`
- `output/clean_3d/cat_clean.glb`

作業:

- リグ付きベースモデルを中央に置く。
- 正面、斜め、横向きの切り抜き画像を参照として配置する。
- Hunyuan3D生成メッシュを横に置き、体型比較用にする。

出力候補:

- `output/rigged/cat_appearance_workbench.blend`

### Step 2: 低リスクな見た目調整

作業:

- マテリアル色を実画像に寄せる。
- 可能であれば部位ごとに色を分ける。
- 形状編集は最小限にする。

出力候補:

- `output/rigged/cat_appearance_v1.blend`

### Step 3: アニメーション破綻確認

確認対象:

- Idle
- Walk
- Jump_ToIdle
- Gallop_Jump

確認内容:

- 脚が極端にねじれないか。
- 体が床下に沈まないか。
- 尻尾が不自然に破綻しないか。
- GLB出力後もアニメーションが残るか。

### Step 4: Task 3Gへ引き渡し

引き渡し内容:

- 調整済みリグ付きモデル。
- 使える既存アニメーション一覧。
- 足りないアニメーション、特にsleep / lie-downの扱い。

## MVPでやらないこと

- 有料APIによる3D生成。
- Tripo / Meshy による外観転写。
- Hunyuan3D高密度メッシュへの直接リギング。
- 完全自動の猫テクスチャ生成。
- 写真そっくりの毛並み再現。
- 自然で高品質な動物アニメーション制作。

## 画像ファイルについての相談ポイント

Task 3F完了後、次の実装に入る前に相談したい点:

1. どの画像を「見た目の正」とするか。
2. 正面、横、斜めのどれを優先するか。
3. 毛色や模様をどの程度まで再現したいか。
4. 体型は実猫に寄せるか、ゲーム向けに簡略化するか。
5. 追加で背面または真横の画像が必要か。

現状の画像でも計画は可能。ただし、実際に見た目を調整する段階では、真横、正面、背面または斜め後ろの全身画像があるほど判断しやすい。

## 結論

Task 3Fの推奨方針は、リグ付きFoxベースを最終可動モデルの土台にし、実画像とHunyuan3D生成メッシュを参照として猫らしさを段階的に加えること。

最初の実装では、形状を大きく壊さず、マテリアル色と軽いプロポーション調整を優先する。高度な自動テクスチャ投影や直接リギングはMVP外とする。
