## 最大の発見: レストポーズがアニメの第1フレームで汚染されていた

**鼻が右にずれて見えた（配色.pdf p5）本当の原因は、テクスチャでも対称化漏れでもなく、
`p2_curl_tail_blender.py` が「たまたま割り当たっていたアクションの第1フレームのポーズ」を
レストに焼き込んでいたこと。**

- スケルトンの blend には `Armature|Walkback` が割り当たったままで、**101本中94本**の
  ボーンが非単位ポーズを持っていた。`bip01_head` は約 **30° 回転**していた。
- `bake_pose_to_rest()` は Armature モディファイアを適用してから `pose.armature_apply` する
  ので、尻尾のカールと一緒にこの頭の回転まで**レスト形状に焼き込まれていた**。
- 追跡すると、鼻の X は `p2_bind.blend` では **-0.00003**（中心）なのに、
  `p2_curled.blend` で **+0.00899** に飛んでいた。

対策: `reset_pose()` を追加し、カール前に全ボーンのポーズを消してアクションを外す。
これだけで **3つのゲート全部が改善**した（特に腹の左右差 35.9mm → 7.9mm）。
左右の非対称に見えていたものの相当部分がこれだった。

**教訓: 「Apply as Rest Pose」の前に、意図したボーン以外のポーズが 0 であることを確かめる。**

### 付随して見つかった罠: Blender は例外を投げても終了コード 0 を返すことがある

`center_head_midline` が落ちたのに `p2_run.py` は前回の `p2_koha.glb` でゲートを回し、
**「PASS」と表示した**。`returncode` だけを見ていると古い成果物で緑になる。
`p2_run.py` は stdout に `Traceback` があれば失敗扱いにするよう修正した。

## 顔（優先度1）

- **鼻を中心に**: 上記のポーズ汚染を直し、さらに `center_head_midline()` で fore スライスごとの
  正中線を測って X=0 に戻す。鼻先 X は **+11.7mm → +0.03mm**。
- **顔を小さく＋三角に**: `HEAD_SCALE` 1.10 → **1.04**。`HEAD_WIDTH_PROFILE` の頬（目の高さ）を
  1.015 → **1.12** に広げ、頭頂を 0.80 に締めて、正面のシルエットを三角に寄せた。
- **目を大きく・横長に**: 目の絵は素材テクスチャに描かれていて 3D の斑では大きくできない。
  `magnify_eye_art()` で**素材の絵をテクセル空間で拡大**する（主軸 ×1.38 / 副軸 ×1.16）。
  拡大の中心は **虹彩の重心**にすること。3D 楕円体のテクセル重心を中心にすると UV の歪みで
  ずれ、暗いまぶた側から拡大されて**瞳が巨大化した真っ黒な目**になる（実際に踏んだ）。
- **耳の前（内側）を肌色に**、**耳の後ろを左右で塗り分け**（下記）。
- 顔の左右: **-X が黒優勢 / +X が茶優勢**（p7・p9・p10・p11 すべてで一貫）。

### 耳の UV を左右で分離した（罠⑪の解消）

耳は左右で**同じ UV 島**を共有しており、「-X の耳の後ろは上が茶・下が黒／+X は茶単色」
（配色.pdf p9）は原理的に作れなかった。UV 占有率は 56.9% しかなく空きが十分あるので、
`separate_ear_uvs()` で **+X の耳の UV 島を空き領域へ平行移動**した（588 ループ）。
移動先が空いていることをスクリプト内で検証している。

平行移動なので、`p3_paint_texture.copy_ear_art()` が**素材テクスチャの同じ矩形を移動先へ複製**
すれば毛のディテールも耳の内側のピンクも保たれる。**両者のオフセットは必ず同じ値にすること**
（`EAR_UV_OFFSET`）。

## 配色（優先度2）

- **後ろ姿を茶色に**（p1「全体的に茶色にする」）: 腰の斑を腿まで広げ、腹側ゲートを緩めた
  (`dorsal_low`)。従来は後ろから見るとほとんど白かった。
- **尻尾**: 「うす茶色と黒を混ぜた感じ」に。`TAN` を茶寄り、`BROWN` を黒寄りにしてコントラストを出した。
- **前脚の黒褐色を +X へ移した**（p3 で追加指示 / p4 で -X のものは「逆側の足にある。削除」）。

### 左右の呼び名は当てにならない。**丸を付けたレンダーの向きで決める**

- 骨は `bip01_l_*` が **+X**（実測 rest x=+0.062）
- キャプチャのラベルは `VIEWS["left"] = (-1,0,0)` = **-X**
- → 名前で決めると必ず反対側に置く。

`配色.pdf` p3 の glb は猫が**画面左**を向く = **+X** のカメラ、p4 の glb は**画面右** = **-X**。
正面像・俯瞰像はどちらも **画面右が +X**（そばかすが +X で画面右に写ることで確認）。
