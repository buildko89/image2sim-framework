# パラメトリックドローン生成 詳細利用手順

## 1. この文書の目的

実測寸法と複数方向の写真から、Blenderでドローンの構造モデルを生成するまでの操作を説明する。
初回セットアップ、既存drone2の再生成、新しい機体設定の作成、生成結果の確認、
Blender MCPを使った調整、問題発生時の確認までを対象とする。

この機能は写真から完成メッシュを自動復元する画像生成AIではない。写真は輪郭と部品構造を判断する
資料として使い、モデルの正しい値はYAMLへ入力した寸法と構成とする。

## 2. 生成処理の全体像

```text
実測寸法・6方向写真
        ↓
機体固有YAML ── テンプレートYAML
        ↓              ↓
scripts/drone_model/run_build.py
  ├─ テンプレート継承
  ├─ 設定検証・モーター位置計算
  └─ Blender 5.2をバックグラウンド起動
        ↓
blender/drone_model/build_drone.py
  ├─ 部品生成と組立
  ├─ アンカー・衝突形状生成
  ├─ 6方向レンダー
  └─ BLEND・GLB出力
        ↓
寸法QA・日本語レポート・比較シート
```

Blender MCPは必須ではない。MCPは生成後のシーン確認や形状調整に使い、正規成果物は常にYAMLと
Pythonスクリプトから再生成する。

## 3. 主要ファイル

| ファイル | 役割 |
|---|---|
| `scripts/drone_model/run_build.py` | コマンド入口、継承、検証、Blender実行、QA、レポート |
| `blender/drone_model/build_drone.py` | Blender内の部品生成、組立、レンダー、エクスポート |
| `config/drone2_model.yaml` | 既存drone2の実測値、部品寸法、写真、出力先 |
| `config/drone_templates/quad_x_guarded.yaml` | 4ロータX型・ガード付きテンプレート |
| `config/drone_templates/multirotor_base.yaml` | 可変ローター数の基礎テンプレート |
| `config/examples/hex6_radial_model.yaml` | 6ロータ放射配置の例 |
| `tests/test_drone_model_templates.py` | テンプレート継承と配置計算のテスト |

## 4. 初回セットアップ

### 4.1 必要環境

- Windows
- Python 3.x
- Blender 5.2 LTS
- Gitで取得した本リポジトリ

Pythonパッケージをインストールする。

```powershell
pip install -r requirements.txt
```

Blenderの標準パスは次の場所である。

```text
C:\Program Files\Blender Foundation\Blender 5.2\blender.exe
```

別の場所へインストールした場合は、生成コマンドへ`--blender`を指定する。

```powershell
python scripts\drone_model\run_build.py `
  --blender "D:\Tools\Blender\blender.exe" `
  --overwrite `
  --skip-contact-sheet
```

### 4.2 Blender MCPについて

MCP接続は通常の生成コマンドには不要である。MCPを利用する場合はBlenderを起動し、MCP拡張を
有効にしてからCodex側で接続する。接続できない場合もバックグラウンド生成は実行できる。

## 5. 最短で動作確認する

写真なしで6ロータ例を生成する。

```powershell
python scripts\drone_model\run_build.py `
  --config config\examples\hex6_radial_model.yaml `
  --overwrite `
  --skip-contact-sheet
```

成功時は次のように表示される。

```

主な確認対象：

├─ hex6_radial.blend
├─ hex6_radial.glb
├─ renders/
├─ resolved_config.json
├─ build_report.json
├─ qa_report.json
└─ BUILD_REPORT.md
```

## 6. 既存drone2を再生成する

### 6.1 写真を配置する

写真比較を行う場合は、公開リポジトリに含まれない実物写真を次の場所へ配置する。

```text
input/raw_photos/drone2/
├─ 上.jpg
├─ 下.jpg
├─ 前.jpg
├─ 後.jpg
├─ 左.jpg
└─ 右.jpg
```

写真の向きは次の定義に合わせる。

| ファイル | 写る方向 |
|---|---|
| `上.jpg` | 機体上面 |
| `下.jpg` | 機体下面 |
| `前.jpg` | 機首正面 |
| `後.jpg` | 機体後面 |
| `左.jpg` | 機体左側面 |
| `右.jpg` | 機体右側面 |

写真は完全な正投影でなくてもよいが、カメラを各面へ正対させ、同じ撮影距離と倍率に近づける。
寸法を読み取る写真には、機体と同じ平面へ定規を置く。

### 6.2 生成する

写真比較シートを含めて生成する。

```powershell
python scripts\drone_model\run_build.py --overwrite
```

写真を使わず形状だけを生成する。

```powershell
python scripts\drone_model\run_build.py --overwrite --skip-contact-sheet
```

`--overwrite`を付けない場合、既存のBLENDまたはGLBがあると処理を停止する。意図しない上書きを
防ぐための動作である。旧版を残す場合は、先に別名または`archive`ディレクトリへコピーする。

## 7. コマンドオプション

```text
--config PATH             機体固有YAML。省略時はconfig/drone2_model.yaml
--blender PATH            blender.exe。省略時はBlender 5.2の標準パス
--overwrite               既存の主要成果物を更新する
--skip-contact-sheet      実物写真との比較シートを作らない
-h, --help                ヘルプを表示する
```

パスはリポジトリルートからの相対パスまたは絶対パスで指定できる。

## 8. 新しい機体を作る前に測る項目

最低限、次を測る。

| 項目 | 用途 | 推奨度 |
|---|---|---:|
| モーター中心位置または中心間距離 | ローター配置 | 必須 |
| プロペラ直径 | プロペラとガードの干渉検査 | 必須 |
| ボディ幅・長さ・高さ | 中央外殻 | 必須 |
| 機体全幅・全長 | ガード込み外形のQA | ガード付きでは必須 |
| モーターハウジング寸法 | モーター外形 | 推奨 |
| アーム幅・厚さ | アーム外形 | 推奨 |
| ガード断面径・高さ | ガード外形 | 推奨 |
| 機体質量・重心 | 物理シミュレーション | 後工程で必須 |

値の情報源には`measured`、`photo_estimated`、`derived`、`placeholder`などを記録する。
写真推定値を実測値として扱わない。

## 9. テンプレート継承

機体固有YAMLの`template_file`で基礎テンプレートを指定する。

```yaml
template_file: config/drone_templates/multirotor_base.yaml
subject_id: my_drone
dimensions_provisional: true
```

機体固有YAMLに書いた値だけがテンプレートへ再帰的に上書きされる。

テンプレート：

```yaml
body:
  width_mm: 40.0
  length_mm: 55.0
  height_mm: 18.0
```

機体固有設定：

```yaml
body:
  width_mm: 46.0
```

解決後：

```yaml
body:
  width_mm: 46.0
  length_mm: 55.0
  height_mm: 18.0
```

解決後の全設定は出力先の`resolved_config.json`へ保存される。設定が想定どおり継承されたかは
最初にこのファイルで確認する。

## 10. ローター配置

### 10.1 `square_diagonal`

対角モーター中心間距離から、4ロータX型の位置を計算する。ローターIDは`fl`、`fr`、`rl`、
`rr`となる。

```yaml
measurements:
  motor_center_diagonal_mm:
    value: 95.0
    source: measured
    tolerance_mm: 1.0

layout:
  mode: square_diagonal
  motor_axis_z_mm: 7.0
```

ガードを`fit_overall`で作る場合は、`overall_width_mm`と`overall_length_mm`も必要である。

### 10.2 `radial`

全ローターを同じ半径へ等間隔に置く。3、4、6、8ロータなどに利用できる。

```yaml
layout:
  mode: radial
  rotor_count: 6
  radius_mm: 55.0
  start_angle_deg: -90.0
  id_prefix: r
  motor_axis_z_mm: 5.0
```

| 項目 | 意味 |
|---|---|
| `rotor_count` | ローター数 |
| `radius_mm` | 機体中心から各モーター中心までの距離 |
| `start_angle_deg` | 1番目のローター角度 |
| `id_prefix` | `r1`、`r2`などの名前に使う接頭辞 |

### 10.3 `explicit`

前後非対称など、等間隔でない配置に使う。Zを省略した場合は`motor_axis_z_mm`が解決済み設定へ
入る。現在の視覚形状の高さは、各部品の`center_z_mm`で共通制御する。

```yaml
layout:
  mode: explicit
  motor_axis_z_mm: 6.0
  motor_positions_mm:
    front: [0.0, -48.0]
    rear_left: [-42.0, 35.0]
    rear_right: [42.0, 35.0]
```

キー名がローターIDとなり、`motor_front`、`rotor_front`、`motor_front_axis`などが生成される。

## 11. 実測値とQA

QA対象にする寸法は`measurements`へ記録する。

```yaml
measurements:
  body_height_mm:
    value: 18.0
    source: measured
    tolerance_mm: 0.5
  body_length_mm:
    value: 60.0
    source: measured
    tolerance_mm: 0.5
  propeller_diameter_mm:
    value: 36.0
    source: measured
    tolerance_mm: 0.5
```

現在、値が存在する場合に自動照合する主な項目は次のとおり。

- 機体全幅
- 機体全長
- ボディ高さ
- ボディ長さ
- ローター数
- 必須部品名の欠落
- Blenderが付ける`.001`などの重複接尾辞

`measurements`は検査基準であり、実際のボディ形状は`body`、プロペラ形状は`propeller`へも
値を設定する。同じ実測値を使う項目が一致しているか確認する。

## 12. ボディ設定

### 12.1 `rounded_box`

角丸直方体。一般的な箱型ボディや初期Blockoutに使う。

```yaml
body:
  shape: rounded_box
  width_mm: 42.0
  length_mm: 60.0
  height_mm: 18.0
  center_z_mm: 0.0
  bevel_mm: 5.0
```

### 12.2 `lofted`

前後端へ向かって幅と高さが減る閉じた外殻。drone2で使用する。

```yaml
body:
  shape: lofted
  width_mm: 34.0
  length_mm: 50.0
  height_mm: 25.0
  center_z_mm: 0.0
  longitudinal_segments: 18
  radial_segments: 32
  width_profile_power: 0.72
  height_profile_power: 1.05
  cross_section_power: 0.78
```

`width_profile_power`と`height_profile_power`は前後方向の絞り方、`cross_section_power`は断面の
丸みを調整する。値を一度に大きく変えず、6方向レンダーを確認しながら調整する。

## 13. アーム、モーター、プロペラ

### 13.1 アーム

```yaml
arm:
  enabled: true
  root_width_mm: 10.0
  tip_width_mm: 7.0
  thickness_mm: 5.0
  root_fraction: 0.34
  center_z_mm: 0.0
```

`root_fraction`は機体中心からモーター中心までの線上で、アーム生成を開始する割合である。
`0.34`なら中心から34%の位置からモーターまでをアームにする。

### 13.2 モーター

```yaml
motor:
  housing_diameter_mm: 11.0
  housing_height_mm: 14.0
  center_z_mm: 3.0
  shaft_diameter_mm: 2.0
  shaft_height_mm: 4.0
```

### 13.3 プロペラ

```yaml
propeller:
  diameter_mm: 50.0
  hub_diameter_mm: 7.0
  hub_height_mm: 3.0
  blade_count: 2
  blade_root_width_mm: 7.0
  blade_tip_width_mm: 4.0
  blade_thickness_mm: 1.2
  blade_root_radius_mm: 4.0
  center_z_mm: 12.0
  direction_pattern: [ccw, cw]
  direction_source: placeholder
```

`direction_pattern`はローター順に繰り返す。特定IDを個別指定する場合は`directions`を使う。

```yaml
propeller:
  directions:
    fl: ccw
    fr: cw
    rl: cw
    rr: ccw
```

各ローターには独立した`rotor_<ID>`ノードと`motor_<ID>_axis`アンカーが作られる。
GLBへ回転アニメーションは埋め込まれていないため、Blenderまたはシミュレータ側で
`rotor_<ID>`を回転させる。

## 14. プロペラガードと脚部

### 14.1 ガードを無効にする

```yaml
guard:
  enabled: false
```

### 14.2 全幅・全長へ合わせる

```yaml
guard:
  enabled: true
  size_mode: fit_overall
  tube_diameter_mm: 2.4
  center_z_mm: 8.0
  inner_gap_deg: 84.0
  major_segments: 48
  minor_segments: 8
  strut_count: 3
  strut_radius_mm: 0.72
```

`fit_overall`は実測全幅・全長とモーター中心範囲からガード外径を計算する。プロペラがガード内径へ
収まらない場合は、Blender起動前にエラーにする。

### 14.3 外径を直接指定する

```yaml
guard:
  enabled: true
  size_mode: explicit
  outer_diameter_mm: 44.0
```

`outer_diameter_mm`は数値または`value`を持つmappingとして指定できる。

### 14.4 脚部

```yaml
landing:
  enabled: true
  leg_diameter_mm: 3.5
  leg_height_mm: 8.0
  leg_center_z_mm: -7.5
  foot_diameter_mm: 5.0
  foot_height_mm: 4.0
  foot_center_z_mm: -12.5
```

不要な場合は`enabled: false`にする。

## 15. 参照写真と出力設定

参照写真は機体固有YAMLへ記録する。

```yaml
references:
  top: input/raw_photos/my_drone/上.jpg
  bottom: input/raw_photos/my_drone/下.jpg
  front: input/raw_photos/my_drone/前.jpg
  back: input/raw_photos/my_drone/後.jpg
  left: input/raw_photos/my_drone/左.jpg
  right: input/raw_photos/my_drone/右.jpg
```

比較シートを作る場合、6方向すべてが必要である。写真がない場合は`references: {}`とし、
`--skip-contact-sheet`を指定する。

出力設定例：

```yaml
output:
  directory: output/my_drone
  blend: my_drone.blend
  glb: my_drone.glb
  resolved_config: resolved_config.json
  build_report: build_report.json
  qa_report: qa_report.json
  render_resolution: 720
```

機体ごとに異なる`output.directory`を設定し、別機体の成果物を上書きしないようにする。

## 16. 生成結果の確認

### 16.1 `qa_report.json`

最初に`status`を確認する。

```json
{
  "status": "PASS"
}
```

`FAIL`の場合は`checks`内の`expected_mm`、`actual_mm`、`error_mm`、`tolerance_mm`を確認する。

### 16.2 `resolved_config.json`

テンプレートと機体固有設定を統合した最終値である。値を直接編集しても次回生成で上書きされる。
修正は元のテンプレートまたは機体固有YAMLへ戻す。

### 16.3 `BUILD_REPORT.md`

使用テンプレート、配置方式、ローター数、入力寸法、派生値、生成寸法を日本語で確認できる。

### 16.4 6方向レンダー

確認順は次を推奨する。

1. 上面でモーター中心、全幅、全長、ボディ輪郭を確認する。
2. 前後面でボディ幅、高さ、アームとガードの高さを確認する。
3. 左右面でボディ長、高さ、機首形状を確認する。
4. 下面で脚部、下面外形、アーム接続を確認する。

## 17. Blender MCPを使った調整

MCPでは次の確認が有効である。

- `MODEL_VISUAL`、`ANCHORS`、`COLLISION`のCollection構成
- `body_core`の寸法
- `motor_<ID>_axis`の位置と回転方向プロパティ
- `rotor_<ID>`と羽根の親子関係
- ガードとプロペラの隙間
- 写真と異なる局所輪郭

推奨手順：

1. 生成済みBLENDをBlenderで開く。
2. MCPからシーンを読み取り、変更前の寸法と部品名を記録する。
3. Blender上では仮調整として形状を確認する。
4. 採用する値を機体固有YAMLまたはPython生成関数へ戻す。
5. バックグラウンド生成を再実行する。
6. QAと6方向レンダーで再現できたことを確認する。

生成済みBLENDだけを直接編集して正規版にすると、次回再生成で変更が失われる。

## 18. 新しい機体を追加する実作業手順

1. `input/raw_photos/<機体ID>/`へ6方向写真を置く。
2. モーター中心、プロペラ径、ボディ3寸法、全幅・全長を測る。
3. `quad_x_guarded.yaml`または`multirotor_base.yaml`を選ぶ。
4. `config/examples/`のYAMLを複製し、固有の`subject_id`と出力先を設定する。
5. `layout`へモーター配置を入力する。
6. `body`、`motor`、`propeller`へ実測値を入力する。
7. ガードと脚部の有無を設定する。
8. 最初は`--skip-contact-sheet`で生成し、構造QAを通す。
9. 6方向写真を登録して比較シートを生成する。
10. MCPまたはBlenderで局所形状を確認し、設定または生成関数へ修正を戻す。
11. 質量、重心、慣性を実測して`physics`へ追加する。

## 19. よくあるエラー

### Blenderが見つからない

```text
FileNotFoundError: Blenderがありません
```

`--blender`で正しい`blender.exe`を指定する。

### 既存成果物がある

```text
FileExistsError: 既存成果物があります
```

旧版を保存してから`--overwrite`を付ける。

### 比較シート用画像がない

```text
比較シートに必要な参照画像がありません
```

6方向すべてを`references`へ指定するか、`--skip-contact-sheet`を付ける。

### プロペラがガードに収まらない

プロペラ径、ガード外径、ガード管径を確認する。`fit_overall`の場合は機体全幅・全長とモーター
中心範囲も確認する。ガード内径は外径から管径2本分を引いた値である。

### QAがFAILになる

`qa_report.json`の誤差を確認し、次のどちらかを修正する。

- 生成形状が誤っている：`body`、配置、ガードなどの生成値を修正する。
- 検査基準が誤っている：`measurements`の値または許容差を修正する。

許容差だけを大きくして形状誤差を隠さない。

### Blenderログを確認したい

出力先の`blender_stdout.log`と`blender_stderr.log`を確認する。Python例外があれば生成処理は失敗扱いに
なる。

## 20. テスト

テンプレート継承、4ロータ対角配置、放射配置、個別配置を確認する。

```powershell
python -m unittest tests.test_drone_model_templates -v
```

Python構文を確認する。

```powershell
python -m compileall scripts\drone_model blender\drone_model
```

既存drone2の回帰生成を確認する。

```powershell
python scripts\drone_model\run_build.py --overwrite --skip-contact-sheet
```

## 21. 現在の制約

- 写真だけから未知の外殻を自動復元しない。
- ボディ形状は`rounded_box`と`lofted`の2種類である。
- `explicit`配置の視覚部品は現在X・Y位置を使用し、高さは部品ごとの`center_z_mm`で共通制御する。
- 複雑なダクト、カメラジンバル、折り畳み機構、上下同軸専用アームは個別実装が必要である。
- GLBへローター回転アニメーションは埋め込まない。
- 質量、重心、慣性、推力係数は外観から確定できないため実測または同定が必要である。

## 22. Git管理上の注意

公開リポジトリでは次をGit管理対象外とする。

- `input/`内の実物写真
- 生成したBLEND、GLB
- 比較シートと6方向レンダー
- Blenderログと一時成果物

Gitへ登録するのは、再生成に必要なYAML、Pythonスクリプト、テスト、日本語文書を基本とする。
