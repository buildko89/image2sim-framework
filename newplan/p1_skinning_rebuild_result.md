## 2. P1-A で何を変えたか

B-6 との差分は**束縛（bind）の方法だけ**である。骨フィットとアニメーションのリターゲット
（`b6b_retarget_animations_blender.py`）はそのまま使った。レストポーズは B-6 でも無傷であり、
壊れていたのは束縛だけだと実測で特定できていたため。

### 捨てたもの（`b6_koha9_mesh_transplant_blender.py` の `bind_mesh`）

距離ゲート + 脊椎に沿ったガウシアンカーネル + Union-Find による毛房の剛体化 +
ラプラシアン平滑化。約200行の自作幾何アルゴリズム。

### 置き換えたもの（`pipeline_v2/p1a_rebind_blender.py`）

すべて Blender 標準機能。自作の重み計算は一行も無い。

1. **重複頂点の統合**（Merge by Distance, 1e-4）。9,282 → 8,764頂点。
2. **主外皮だけを取り出したプロキシに Automatic Weights**（ボーンヒート）。
   B-6 が「毛房の非連結パーツで全滅」したのは、毛房ごと一括でバインドしようとしたため。
3. **実メッシュへ Data Transfer**（Vertex Group / Nearest Face Interpolated）。
   毛シェルと小片はここでウェイトを受け取る。
4. **ウェイト平滑化**（`vertex_group_smooth`, factor 0.5, repeat 10）。
5. **Limit Total 4 + Normalize All**。

尻尾のカールは行わない（P2 の担当）。1フェーズ = 1関心事。

## 3. 前提調査で分かったこと

`pipeline_v2/p1_inspect_mesh_blender.py` / `p1_inspect_components_blender.py` で実測。

**「本体」メッシュ `Koha9Body` は単一の閉じたメッシュではない。**

| | 素の状態 | 重複頂点統合後 |
|---|---|---|
| `Koha9Body`（本体） | 7,563頂点 / 35成分 / 境界辺1,477 / 重複518 | 7,045頂点 / **13成分**（主外皮 6,659頂点、境界辺185、非多様体辺2） |
| `Koha9Tail`（毛シェル） | 1,719頂点 / **78成分** | 変化なし（毛カード1枚 = 19頂点） |

主外皮を切り出せばボーンヒートは通る。浮いている小片（頭部付近のヒゲ・耳毛）と
毛シェルは Data Transfer で受け取れる。**「標準手法が通らない」は「メッシュの前処理が
足りない」のサインであって、「アルゴリズムを書け」のサインではなかった。**

## 4. 破綻箇所の特定と潰し方（`pipeline_v2/qa_locate_tears.py`）

裂けた辺の支配ボーンを集計する道具を新設し、2回の反復で閾値を下回らせた。

### 反復1: 標準手法に置き換えただけ → 3アニメ PASS / 5アニメ FAIL（0.09〜1.11%）

破綻の支配ボーン上位: `bip01_l_forearm`, `bone015`, `bone018`, `bip01_r_upperarm`,
`bone007`, `bone017`。3つのクラスタに分かれていた。

- 四肢の関節（肘・肩・股関節）
- **`bone001`〜`bone015`** — ヒョウ由来の頭部補助ボーン（顎・目・耳）。
  koha9 の頭に対応先が無く、無関係な頂点を掴む。
- 尻尾（`bone016`〜`020`）と毛シェル

### 反復2: 3つの標準的な対処 → 7アニメ PASS / Jump のみ FAIL（0.541%）

- 頭部補助ボーン `bone001-015` を **`use_deform = False`**（リグの設定であり自作処理ではない）。
  頭は `bip01_head` に剛体追従させる。顎も耳も動かさない。
- ウェイト平滑化を導入。
- 毛シェルの破綻は消滅（74頂点 → 0）。

残った Jump の破綻を再度 `qa_locate_tears.py` で見ると、`s_fxtop` が上位に現れた。

### 反復3: `s_fxtop` / `s_fxtop_0` も非デフォーム化 + 平滑化を repeat 10 へ → **全8アニメ PASS**

**`s_fxtop` はヒョウの補助ボーンで、`b6b` のリターゲット対象リストに入っていない。**
つまりレストに取り残されるのに、ボーンヒートは胸〜首の頂点を掴む。頭が動くと必ず裂ける。
`b6b_retarget_animations_blender.py:37` の `DEFORM_BONES` と、実際にデフォームするボーンの
集合がずれていたことが原因。

> **教訓:** アニメーションのリターゲット対象に入っていないボーンは、デフォームさせてはならない。
> この不一致は静止画では絶対に見つからない。

## 5. 目視ゲート

`python pipeline_v2/p1_capture.py --glb <GLB> --prefix <名前>` で
4方向（front/left/right/back）× 全8アニメ × 3フレーム = 96枚を Godot 4.6 で撮り、
コンタクトシートに組む。背景を緑にして、穴や欠損が一目で分かるようにしてある。

- 概観: `output_v2/reports/p1_contact_p1a_overview.png`
- アニメ別: `output_v2/reports/p1_contact_p1a_<anim>.png`

**P1-A**: 4方向すべてで破片・欠損・貫通なし。Idle1 の前脚も完全。
尻尾の先端を正面から見ると背景の緑が透けるが、これは毛カード（alphaMode BLEND）の
フリンジであって胴体の穴ではない。

**P1-B**: **Jump の行が空になる。** ルートモーションが焼き込まれたままなのでフレーム外へ飛ぶ
（B-5 の記録どおり）。加えて顔と体型がヒョウのまま、B-3 の手続き三毛テクスチャは白く抜けて
koha に似ていない。

> Godot の `MeshInstance3D.get_aabb()` はスキン付きメッシュで当てにならない
> （アーマチュアの 0.0009 スケールが効いて 1/1000 の箱が返る）。カメラのフレーミングは
> Python 側で GLB のレスト頂点から実測して渡している。

## 6. 既知の制限（P1 では追わない）

- **`bip01_l_hand` / `bip01_l_foot` にウェイトが乗っていない。** ボーンヒートが届かないか、
  平滑化と Limit Total 4 で消えている。肉球は前腕・飛節に剛体追従する。
  つま先が曲がらないが、もふもふの短足では視認できず、機械ゲートも目視ゲートも通る。
  追うなら P4（アニメーション）でまとめて。
- Jump の破綻辺 0.356% は基準線（0.13〜0.16%）の 2倍強。閾値内だが最も余裕が無い。
- 尻尾はまっすぐ後ろに伸びたまま。**P2 で骨のポーズを Apply as Rest Pose して巻き上げる。**
- 見た目は素材アセットそのまま。**P3 で raw_photos に寄せる。**
