## 4. 実装ステージ

1. **P4-1 Jump 切り出し** — **完了（2026-07-15）**: ビート実測（骨盤・頭・四肢の高さの時系列）で
   タメ 397-429 / ピーク 441 / 着地 461-473 / 復帰 489 を特定し、**f397-489（1.53s）に切り出し**。
   道具は `pipeline_v2/p4a_trim_action_blender.py`（汎用）、ランナー 4.97/6 に組み込み済み。
   ゲート PASS（Jump 皮膚 0.468%/毛 0.648% — 詰め物が消えた分の見かけ上昇）。元の 581f は
   `output_v2/backup_p4anim_20260715/` に保全。**着地の床めり込み: 実測で t≈1.05〜1.35s に
   最大 -0.129m（約13cm）まで頭・前足が床下へ回り込む**（全ボーン回転キーのみ＋骨盤高さ固定で、
   着地の前傾により幾何学的に頭が床下へ。測定 `scratchpad/floor_probe.py` 相当）。
   **対処方針の決定（2026-07-16, ユーザー）: 「今はこのまま」— Godot 側でジャンプの上下動
   （放物線）をコードで与えて相殺する前提**。単体プレビュー GIF ではめり込みが見えるが実害なし。
   在庫の対処手段（着地窓の短縮 / 骨盤リフトキー）は必要になったとき使う。
2. **P4-2 ネコパンチ** — **完了（2026-07-16）**: 実測で素の Atk は左前脚の弱い「持ち上げ」
   （前後66mm/上下45mm、ピーク中盤）で、当初案の「時間リマップ+振幅拡大」では前への突きに
   ならないと判明（振幅を上げても持ち上げが大きくなるだけ）。方針変更し、前脚チェーンを毎フレーム
   「レスト＋ワールドX軸まわりの前方スイング」に置き換えて突きをオーサリングする道具
   `pipeline_v2/p4_punch_author_blender.py` を新設。プロファイル（構え→振りかぶり→突き→保持→
   戻し）を焼き、最後に時間圧縮。**当初は「前方へ突き」で作ったがユーザーに『下から上のアッパー
   になっている。猫は上から下 or 横(フック)が正解』と指摘され、mode 対応に作り直した。**
   Atk1=**左手の上から下の振り下ろし**（side=l, mode=downward, raise-170°/strike-12°。前足先 Z
   0.01→0.22→0.03）、Atk2=**右手の横フック 右→左**（side=r, mode=hook, lift-92°/sweep55°。右前足先
   X -0.08→-0.17→+0.02 の横薙ぎ）で差別化（手も振り方も変える。ユーザー決定 2026-07-16）。
   左右は --side、振り方は --mode で切替可（右手は検証済み・ゲートPASS）。
   体幹・頭・尻尾の元カーブは二次モーションとして残す。ランナー 4.98/4.99 に組込。ゲート2本 PASS
   （Atk1 皮膚0.264%/Atk2 0.273%、腹42.5%）。**罠㉓: この rig の前脚は use_connect=False。
   pb.matrix にワールド回転を前掛けするとボーンの頭ごと原点周りに飛んでメッシュが棘状に裂ける。
   頭(位置)を保って姿勢だけ回すこと（swing_inplace）。㉔: 前脚の速い上下・横は 20コマシート＋
   俯瞰カメラでは読めない。数値で前足先(hand tail)のワールド軌跡を出して検証する（scratchpad/
   paw_traj.py 相当）。** 参照: 1681033045356。
3. **P4-3 再生速度 + Walk の尻尾「?」** — **完了（2026-07-16）**:
   ①**再生速度**: ユーザー判断で「現状のままでOK」（Walk/Walkback 1.33s・Run 0.50s・Idle1 2.5s・
   Idle2 7.5s は変更なし）。※コンタクトシートは等間隔サンプルで実物の歩数刻みを測れないため、
   倍率は素材から算出できず見た目の好みで判断。②**Walk の尻尾「?」**: 道具 `p4_tail_hook_blender.py`
   を新設。尻尾上半分(bone017-020)を前方(頭側 -Y)へ緩くアーチさせ、先端を約100mm前へ出して
   「尻尾立て＋前方フック」に（curl 017=20/018=30/019=34/020=28°）。**当初は先端(019/020)だけ
   50/85°と強く巻いたが、巻きすぎて先端が軸線近くへ戻り「まっすぐ」に見えた（ユーザー指摘）**。
   上半分に分散した開いたアーチにして解決。ランナー 4.995 に組込。ゲート PASS（Walk 皮膚0.066%）。
4. **P4-4 香箱座り + お座り** — **完了（2026-07-16）**: 汎用ポーズ道具
   `pipeline_v2/p4_pose_action_blender.py` を新設（JSON で world 軸回転を親→子に加算＝罠㉓、
   最下点が Z=0 に来るようルートを自動接地、新規アクション化、胸の呼吸微動でループ）。ポーズは
   `p4_pose_loaf.json` / `p4_pose_sit.json`。ランナー 4.996/4.997 に組込。ゲート PASS
   （Loaf 皮膚0.091% / Sit 0.270%）。
   **rig の重要な制約（判明）: 前脚が首の子（clavicle→neck）＋前脚が短い（長さ0.12）ため、
   上体を垂直近くまで立てると肩が上がり前足が床から浮く（Z0.10以上）。よって背筋を立てた
   お座りは不可。ユーザー決定で「香箱優先＋お座りは頭を上げたコンパクト座り（前足接地は簡略）」で妥協。**
   後脚は bip01_spine の子なので bip01_spine を回すと後脚も動く（胴を立てるなら spine1 以降）。
   脚を畳む符号: thigh/calf とも負で前方へ畳む。速い脚の上下は数値（bone tail のワールド座標）で検証。
   **尻尾は下ろして床に接地（ユーザー要望 2026-07-16「通常ネコは尻尾を下している」）。当初は背に
   上げていたが変更。尻尾を強く下げると先端が床下へ潜り自動接地が全身を持ち上げて足が浮くため、
   接地判定(min_world_z)は尻尾ウェイト頂点を除外し（体・足で接地）、尻尾は「尻尾込み minZ ≒ 0」に
   なるよう角度を調整（Loaf bone016-020 = -55/-35/-22/-13/-7、Sit = -49/-33/-21/-12/-6）。**
5. **（任意）P4-5 尻尾の振り抑制**: Jump ゲートの余裕拡大を兼ねる。

各ステージの完了条件: ゲート2本 PASS + 1440px 目視 + strips GIF での動きの確認。
