# 🔄 プロジェクト方向性リセット計画 v1

> **作成日:** 2026-07-08  
> **目的:** 画像ファイルからネコの3Dモデルを作成するプロジェクトの方向性を再検討し、実行可能なルートを提案する

---

## 1. プロジェクトの原点と現在地

### 1.1 元々の目標

```
実在するネコ（三毛猫・マンチカン）の写真 → ゲームエンジンで動かせる3Dモデル
```

- 入力: ネコの写真 10〜30枚（正面・横・斜め等）
- 出力: リグ付き・テクスチャ付き・アニメーション付きの3Dモデル（GLB/FBX）
- 表示先: Godot / Unity / Unreal Engine

### 1.2 これまでの経緯サマリー

| Phase | やったこと | 結果 |
|-------|-----------|------|
| Phase 1 | Tripo API で静的3D生成 | 方針転換: 無料/ローカル優先へ |
| Phase 2 | TripoSR / Hunyuan3D で形状生成 | メッシュは生成できたが静的のみ |
| Phase 3 | Fox(キツネ)ベースモデルに外見転写 | ❌ 失敗: キツネ骨格では猫に見えない |
| Phase 4 | 既存猫モデル(input/cat)を調査 | 複数の猫アセット発見 |
| Phase 5 | 猫モデルにカメラプロジェクション | ❌ 失敗: ポーズ不一致・UV破綻 |
| Phase 6 | パレット抽出 → 頂点カラーベイク | cat_palette_vertex_bake_pass.glb 生成 |
| Phase 7 | Godot で確認 | ❌ 巨大な異形オブジェクトが出力された |
| **現在** | **方向性の再検討が必要** | |

### 1.3 確認された問題（確認.png の分析）

確認画像では、Godot のインポート画面にて：

| 観察項目 | 状態 |
|---------|------|
| モデル形状 | 四肢が極端に伸び、十字型の巨大オブジェクトに見える |
| メッシュ構成 | `Cat_Mesh_CatGirl2_cat_hou...` 等、元のモデル名が残存 |
| アニメーション | Cat_Idle, Cat_Punch 等は存在 |
| テクスチャ | 適用されているが形状が崩壊しているため確認不可能 |

**根本原因の推定:** ベースモデル（`cat_animated.blend`）が Fox モデルから変形を重ねたもので、各パスでのスケール・デフォーム操作が累積し、エクスポート時に骨格変形が巨大化した。

## 2. これまでのアプローチの何が問題だったか

### 2.1 構造的な問題

| # | 問題 | 詳細 |
|---|------|------|
| ❌ 1 | **Fox → Cat 変形戦略の失敗** | キツネの骨格・プロポーションは猫と根本的に異なる。Shape Key や Python での変形だけでは限界がある |
| ❌ 2 | **カメラプロジェクションの失敗** | 写真のポーズと3Dモデルのレストポーズが一致せず、UV展開にも破綻が発生 |
| ❌ 3 | **パイプライン複雑化** | 57本のスクリプト、60以上のドキュメントが蓄積。どのスクリプトが最新かの管理が困難 |
| ❌ 4 | **累積変形** | 各タスク (55→56→57→...→81) で`.blend` を次々加工し、変形エラーが蓄積 |
| ❌ 5 | **ゴール不明確化** | 「写真から3Dモデルを作る」→「既存モデルにテクスチャを貼る」にゴールがずれた |

### 2.2 AIによる3Dモデル生成の現実

> **結論: 画像から3Dモデルを作ること自体は可能。ただし「リグ付き・アニメーション付き」を一発で得ることは2026年時点でも難しい。**

#### 2026年現在のAI 3D生成の実力

| 能力 | 成熟度 | 説明 |
|------|--------|------|
| 画像 → 静的メッシュ | ⭐⭐⭐⭐⭐ | TRELLIS 2, Hunyuan3D 等で高品質な静的モデルが生成可能 |
| テキスト → 静的メッシュ | ⭐⭐⭐⭐ | プロンプトから3Dモデル生成も高品質化 |
| PBRテクスチャ自動生成 | ⭐⭐⭐⭐ | baseColor, roughness, metallic 等の同時生成 |
| 自動リトポロジー | ⭐⭐⭐ | ゲーム向けの最適なメッシュ密度への変換 |
| 自動リギング（人型） | ⭐⭐⭐⭐ | Mixamo, AccuRIG が成熟。ただし**人型限定** |
| 自動リギング（四足動物） | ⭐⭐ | **猫等の四足動物のフル自動リギングは未成熟** |
| アニメーション自動生成 | ⭐⭐ | 人型のモーションは充実。動物は手動が必要 |
| 写真 → リグ付きアニメモデル（End-to-End） | ⭐ | **一発では実現不可能** |

#### 重要な気づき

```
写真 → [AI生成] → 静的メッシュ ← ここまでは現実的
静的メッシュ → リトポ → リギング → アニメーション ← ここは手動工程が必要
```

つまり、このプロジェクトの最大の難所は **「AI生成した静的メッシュを、動かせるキャラクターにする工程」** にある。

## 3. 提案する3つのルート

### 概要比較

| ルート | 名称 | 難易度 | 品質 | 必要スキル | 期間目安 |
|--------|------|--------|------|-----------|---------|
| **A** | AIメッシュ生成 + 既存リグ転写 | ⭐⭐⭐ | ⭐⭐⭐⭐ | Blender中級 | 2〜4週間 |
| **B** | 既存猫モデル + AI テクスチャ生成 | ⭐⭐ | ⭐⭐⭐ | Blender初級 | 1〜2週間 |
| **C** | フォトグラメトリ + 手動リギング | ⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | Blender上級 | 4〜8週間 |

---

### Route A: AIメッシュ生成 + 既存リグ転写（推奨）

> **「AIで猫の形を作り、既存のリグ付きモデルの骨格を移植する」**

```
猫写真 → TRELLIS 2 / Hunyuan3D → 静的メッシュ → Blender リトポ → リグ転写 → ウェイトペイント → アニメーション → テクスチャ → GLB/FBX → Godot
```

#### 詳細ステップ

| Step | タスク | ツール | 説明 |
|------|--------|--------|------|
| A-1 | 高品質静的メッシュ生成 | TRELLIS 2 or Hunyuan3D | 正面・横のネコ写真から3Dメッシュを生成。複数ツールで生成し比較 |
| A-2 | メッシュクリーンアップ | Blender | リトポロジー（Instant Meshes or Blender Remesh）、UV展開 |
| A-3 | リグ転写 | Blender | `input/cat2/koha9_cat` のスケルトン（Armature）を生成メッシュに適用 |
| A-4 | ウェイトペイント | Blender | 自動ウェイトで初期設定後、問題箇所を手動修正 |
| A-5 | アニメーション | Blender | 既存アニメーション（Idle, Walk, Run）をリターゲット or 新規作成 |
| A-6 | テクスチャ | Blender + AI | 写真ベースでUVにペイント or AI テクスチャ生成ツール使用 |
| A-7 | エクスポート・検証 | Blender → Godot | GLB出力 → Godot でインポート・アニメーション再生確認 |

#### メリット・デメリット

| メリット | デメリット |
|---------|----------|
| AI生成メッシュが写真のネコに最も近い形状 | リグ転写にBlender中級スキルが必要 |
| koha9_cat のリグを再利用可能 | ウェイトペイント調整に手間がかかる |
| 最新のAI技術（TRELLIS 2等）を活用 | AI生成メッシュのトポロジーが荒い場合がある |

#### 必要なツール

- **TRELLIS 2** (MIT License, 16GB+ VRAM推奨) or **Hunyuan3D** (無料Web版あり)
- **Blender 4.x / 5.x**
- **Instant Meshes** (リトポロジー用, 無料)

---

### Route B: 既存猫モデル + AIテクスチャ生成（最速・手堅い）

> **「すでにあるリグ付き猫モデルを使い、テクスチャだけをAIで写真風にする」**

```
input/cat2/koha9_cat → Blender プロポーション微調整 → 写真からカラーパレット抽出 → Blender テクスチャペイント → GLB/FBX → Godot
```

#### 詳細ステップ

| Step | タスク | ツール | 説明 |
|------|--------|--------|------|
| B-1 | ベースモデル選定 | - | `input/cat2/koha9_cat` (scene.gltf) をベースに採用 |
| B-2 | プロポーション微調整 | Blender | 短足・丸顔・もふもふ尻尾等をスカルプト/Shape Keyで微調整 |
| B-3 | カラーパレット抽出 | Python (既存 `080_extract_cat_color_palette.py`) | 写真からK-means でカラーパレット抽出（**この部分は既存コードを再利用可能**） |
| B-4 | UV テクスチャペイント | Blender | 既存UV (`Koha9Tail_baseColor.png`) の上に、パレット色で三毛猫パターンを手動 or スクリプトでペイント |
| B-5 | エクスポート・検証 | Blender → Godot | GLB出力 → アニメーション再生確認 |

#### メリット・デメリット

| メリット | デメリット |
|---------|----------|
| **最速で結果が出る**（リグ・アニメーションは最初から存在） | モデル形状が「写真のネコ」とは完全一致しない |
| 既存コード（パレット抽出）を再利用可能 | koha9_cat が「自分のネコ」に見えるかは限界がある |
| スクリプト累積問題を回避（新規パイプラインで最小構成） | クリエイティブな手動作業（テクスチャペイント）が必要 |
| 失敗リスクが低い | 3Dモデルの「AI生成」という技術的チャレンジは少ない |

#### 注意点

> ⚠️ **これまでの失敗（cat_palette_vertex_bake_pass.glb）との違い:**  
> 以前のアプローチは Fox モデルを何度も変形した `cat_animated.blend` を入力にしていたため、累積変形が崩壊を招いた。  
> Route B では **未加工の koha9_cat モデルを直接使用**し、最小限の変更だけを行う。

---

### Route C: フォトグラメトリ（最高品質・上級者向け）

> **「大量の写真から実物そっくりの3Dメッシュを再構成する」**

```
ネコの写真 50〜200枚撮影 → Meshroom フォトグラメトリ → 高密度メッシュ → Blender リトポロジー → リギング(手動) → アニメーション → GLB/FBX → Godot
```

#### メリット・デメリット

| メリット | デメリット |
|---------|----------|
| **最もリアルな結果**（実物のネコを忠実に再現） | **撮影が最大の難関**（ネコが動く、協力してくれない） |
| テクスチャもリアル（実写テクスチャ） | 50〜200枚の多角度写真が必要 |
| 確立された技術（新しいAIに依存しない） | リトポロジー + リギング + アニメーションは全て手動 |

> ⚠️ **現実的な課題:** 生きたネコの全方位写真を撮影するのは非常に困難です。ネコは動き回るため、フォトグラメトリに必要な「静止した被写体の多角度撮影」との相性が悪い。

## 4. 推奨ルートと理由

### 推奨: Route B 先行 → Route A 本命

```
Phase 1 (1週間): Route B で「動くネコ」をまず1体完成させる
Phase 2 (2〜3週間): Route A で「写真に近いネコ」のAIメッシュ生成に挑戦
Phase 3 (必要に応じて): Route A のメッシュが十分な品質なら、リグ転写して最終版に
```

#### 理由

1. **Route B で早期に成功体験を得る** — koha9_cat はリグもテクスチャも最初からあるため、テクスチャを変更するだけで「動くネコ」が Godot で確認できる。モチベーション維持に重要。

2. **Route A で本命のAIメッシュ生成に取り組む** — TRELLIS 2 や Hunyuan3D で写真から生成した静的メッシュに、koha9_cat のリグを転写する。これが成功すれば「写真からネコの3Dモデルを作る」という本来の目標を達成できる。

3. **累積変形問題を回避** — 新しいパイプラインでは、中間 `.blend` ファイルを次々加工するのではなく、**各ステップを独立したスクリプトとして実行**し、入出力を明確にする。

## 6. 技術選定（2026年7月時点）

| ツール | ライセンス | VRAM | 推奨度 | 理由 |

| ツール | 用途 | 備考 |

## 8. リスクと対策

| リスク | 影響 | 対策 |
|--------|------|------|
| TRELLIS 2 のセットアップが困難 | Route A 遅延 | Hunyuan3D Web版をフォールバック |
| AI生成メッシュのトポロジーが荒い | リグ転写失敗 | リトポロジー工程（R-8）を入念に |
| koha9_cat のリグが猫形状に最適化されていない | アニメーション品質低下 | Route B でまず確認、問題あれば `input/cat/` の他モデルに切替 |
| ウェイトペイント調整に時間がかかる | 全体遅延 | 自動ウェイトで80%を目指し、完璧主義を避ける |
| ネコの写真枚数が不足 | AI生成品質低下 | 最も良い1枚で生成 → 足りなければ追加撮影 |

## 9. まとめ

### 「画像からネコの3Dモデルを作る」ことは可能か？

> **✅ 可能です。ただし、ワンクリックで完成するものではありません。**

2026年現在のAI技術では：
- **静的メッシュの生成**（画像 → 3Dモデル）は非常に高品質で実用的
- **リギング・アニメーション**は自動化が不十分で、特に四足動物は手動工程が必要
- **テクスチャ**はAI生成ツールが進歩しており、写真からの色転写も可能

### 次のアクション

1. **このプランの方向性について確認**（Route A / B / C の選択）
2. Route B（koha9_cat + テクスチャ変更）から着手し、早期にGodotで動くネコを確認
3. 並行して Route A（AI メッシュ生成）のツールセットアップを開始

> **最も重要な教訓:** 中間ファイルを次々と変形するチェーンパイプラインは避け、各ステップの入出力を明確にした**独立タスク方式**で進める。
